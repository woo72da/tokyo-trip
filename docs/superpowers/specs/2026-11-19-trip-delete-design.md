# 여행 삭제 (S-6 일부) — 짧은 설계

**왜:** 여행을 만들 수는 있는데 지울 방법이 없다. 실기기 테스트용 '시험 여행'을 정리하고 싶다.

**정한 것 (사용자 승인 2026-11-19)**
- 여행 주인(owner)만 삭제. 초대받은 사람은 지금처럼 '이 여행에서 나가기'.
- 위치: 설정 › 여행, 함께하는 사람 목록 아래. 주인에게는 '나가기' 자리에 `.btn.danger.wide` + 휴지통 "이 여행 삭제". (DESIGN.md: 목록 줄에는 삭제를 두지 않음)
- 지금 보는 여행을 지운다. 지운 뒤 남은 여행(도쿄 우선)으로 옮기고, 없으면 '내 여행 만들기' 상태.
- 앱에 들어 있는 도쿄 여행(`slug = TRIP_SLUG`)에는 버튼을 보이지 않는다.
- 확인 창 `askConfirm`(danger): 일정·경비·예약번호·사진이 모두 지워지고 되돌릴 수 없음, 여행메이트 화면에서도 사라짐.
- 순서: 서버 사진(`docs/<tripId>/…`) → `trips` 행 삭제(멤버·초대·기록·예약번호는 DB에서 cascade) → 이 폰의 그 여행 기록·사진.
- 다른 폰: 목록을 다시 받을 때 사라진 여행이면 다른 여행으로 옮기고 "보던 여행을 더 볼 수 없어요" 알림, 남은 폰 기록(stash)도 정리.

**SQL:** 필요 없음. `trips_delete` 정책(is_owner)과 cascade가 이미 있다.

**접근 방법:** 나가기(`mateLeave`)와 같은 자리·같은 흐름을 따른다. 다른 후보였던 '목록 줄 삭제'는 디자인 규칙 위반, '여행 관리 팝업'은 이 정도 기능에 화면이 하나 늘어나서 뺐다.

**계획:** `app.js`만 수정.
1. `tripDelete()` — 주인·온라인·도쿄 아님 확인 → 확인 창 → 사진 목록 지우기 → trips 삭제 → 다른 여행이 있으면 `tripSwitch`로 옮긴 뒤 지운 여행 stash 제거, 없으면 이 폰의 여행 기록·사진을 비우고 `cloudTrip` 비움 → `cloudStart(true)`.
2. `mateListHtml` — 주인이고 도쿄가 아니면 `data-trip-del` 버튼. 클릭 위임 목록·분기에 추가.
3. `cloudFindTrip` — 목록을 받으면(비어 있지 않을 때) 목록에 없는 `stash:<uuid>`와 `stash|<uuid>|` 사진 정리, 보던 여행이 사라졌으면 알림.
4. 버전 v299, DESIGN.md 행 추가. 확인: `node --check app.js`, 로컬 미리보기에서 버튼 노출 규칙 확인, 폰에서 시험 여행 삭제.
